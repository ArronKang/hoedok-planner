# 앱 재구성 설계 (프로토타입 v3)

## 이 앱을 쓰는 이유 (한 줄)
종이 플래너로는 안 되는 것 — **체크하면 진도가 저절로 채워지고, 그게 숫자와 그림으로 보인다.**

## 원칙
1. **겉은 아주 단순하게, 들어갈수록 깊게.** 처음 보이는 건 "오늘 할 일"과 체크 버튼뿐이다. 나머지는 누르거나 열어야 나온다.
2. **자주 하는 일일수록 얕은 곳에.** 매일 → 한 번 탭(체크). 가끔 → 두 번(항목 눌러 미루기·일부만). 드물게 → 메뉴 속(고치기, 다시 나누기, 설정).
3. **입력은 처음 한 번, 그 뒤로는 체크만.** 시험·과목·교재만 넣으면 회독 단계와 날짜별 할 양은 앱이 만든다.
4. **무엇을 고르든 예쁘게.** 색·글꼴·간격·배치는 자유 입력이 아니라 미리 설계한 선택지에서 고른다. 과목 색은 한 팔레트 안에서만, 태블릿 화면 나누기는 정해진 비율로만.
5. **판단은 사용자가.** 예측·추천·연속 기록·배지 없음. 사실 수치만.
6. **관련될 때만 나타난다.** 지난 날 못 끝낸 일 알림, 가장 적게 본 곳 같은 정보는 해당할 때만 한 줄로 뜬다.
7. **움직임은 알려 주려고만, 부드럽게, 끌 수 있게.** 무엇이 나타나고 사라졌는지 알려 주는 짧은 페이드만 쓴다. 튀거나 반복되거나 축하하는 움직임은 없다. 움직임 때문에 기다리게 하지 않는다. 설정에서 속도를 고르거나 끄고, 기기의 '동작 줄이기'를 따른다. 새 움직임은 [움직임-버그-체크리스트.md](움직임-버그-체크리스트.md)를 통과해야 한다.
8. **알맹이 (베타 1.0~).** 보이는 글자·칸·숫자마다 '왜 거기 있는지'가 있어야 한다. 기능을 늘리기보다 이미 있는 것이 정확하게 맞게: 보이는 값 = 저장된 값, 말없이 무시하지 않기(고쳤으면 한 줄로 알려 주기), 적은 진도는 함부로 지우지 않기, 기기 기본 동작(스크롤·창 끌기·탭 다시 누르기)을 흉내 내지 말고 그대로 쓰기.
9. **단위는 교재마다.** 쪽은 읽은 데까지, 지문·문제·강·회·단원은 칸을 골라 채운다. 단원은 이름(1-1, 1-2…)을 붙일 수 있다. 단위가 섞이면 비율은 걸리는 시간으로 낸다.

## 층
| 층 | 휴대폰 | 태블릿 |
|---|---|---|
| 0 (겉) | 오늘 · 진도 · 성적 3개 탭 | 왼쪽 막대 3개 + 오늘 옆에 진도가 함께 보임 |
| 1 (한 번 누르면) | 할 일 자세히(다 했어요/일부만/내일로), 과목 진도(막대·숫자 4개·단계), 시험 결과 | 같음, 목록+자세히 두 칸 |
| 2 (더 들어가면) | 할 일 더 보기(메모·시간·마감·반복), 최근 2주, 가장 적게 본 곳, 단계 고치기, 과목별 성적 계산, 돌아보기(한 주 / 시험 준비 전체), 반복하는 일 모아 보기 | 같음 |
| 3 (설정) | 애플 설정처럼: 계정 카드 → 화면 및 밝기(디자인·밝기·강조 색) · 글자(글꼴·굵게·크기·간격) · 탭 막대와 배치(유리/기본·탭 이름·앱을 열면) · 움직임(속도·화면 옮길 때·진동) → 오늘 화면 · 진도 화면 · 달력과 시각 → 공부(시험·과목·공부 가능 시간) → 홈 화면에 추가 · 기록 관리 · 정보 | 같음 (탭 막대 대신 태블릿 화면 나누기) |

- 아래 막대: 아이폰은 화면 위에 떠 있는 유리 막대 + 같은 줄의 동그란 ＋ (리퀴드 글래스), 나머지는 화면에 붙은 기본 막대 + 막대 바로 위 ＋. 설정에서 고를 수 있다.
- 단위·칸(2층): 교재 줄의 단위를 눌러 바꾸고, 단원 이름은 그 아래 '이름 고치기'. 칸 교재는 과목 화면(1층)에서 칸을 바로 채운다.
- 겉(0층)에 새로 생긴 것은 **그때만 뜨는 한 줄**뿐이다: 브라우저로 열었을 때 '홈 화면에 추가'(닫으면 다시 안 뜸), 예시를 보는 중일 때 '내 기록으로 시작', 로그인이 풀렸을 때 설정 단추의 점.

## 버전
- `docs/mockups/v3/` — **원본(기본)**. 파일을 읽기 전용으로 잠가 두었고 고치지 않는다.
- `docs/mockups/v4/` — v3 복사본 + [개발-계획.md](개발-계획.md)의 A(시험 주기·지문별·틀린 이유·할 일 필드·성적 구조).
- `docs/mockups/v5/` — v4 + 날짜별 공부 시간·예상/실제 시간·내신 흐름·백업·사진·학기 이름.
- **실제 앱**(`src/app/`)은 v5 화면을 그대로 옮긴 것이다. 화면을 바꿀 때는 프로토타입에서 먼저 시험하고 옮긴다.
- 새 기능을 시험할 때는 마지막 버전을 복사해 v5, v6…을 만들고 `prototype.html` 목록에 한 줄 더한다. 기록 저장 이름(`hoedok-proto-N`)도 버전마다 바꾼다.
- 실제 앱이 공개된 뒤(2026-09-30)로는 **git 브랜치가 복사본 역할**을 한다. `main`은 폰에서 쓰는 버전, 새 기능은 따로 만든 브랜치에서 만들고 사용자가 확인한 뒤에 합친다. 무엇이 바뀌었는지는 [변경기록.md](변경기록.md).
- **수정본은 언제나 미리 보기로 먼저 올린다** (사용자 요청 2026-10-01): https://arronkang.github.io/hoedok-planner/preview/
  - `python tools/preview.py "무엇을 바꿨나" --push` — 지금 브랜치를 main의 `preview/` 폴더로만 올린다. 실제 앱 파일은 그대로라 폰에 '새 버전' 알림이 뜨지 않는다.
  - 미리 보기는 저장 이름이 모두 `preview.`로 시작해서(`src/env.js`) 실제 기록과 섞이지 않는다. 같은 계정으로 로그인할 수 있지만 서버의 기록 공간이 따로다(`preview:`). 맨 위 주황색 줄로 미리 보기임을 늘 보여 준다.
  - 홈 화면에 '미리 보기'(주황 아이콘)로 따로 설치해 앱처럼 연다. 설치해 두면 새로 올릴 때마다 저절로 최신본이 열린다.
  - PC에서만 먼저 보려면 `python tools/preview.py "시험" --local` → http://localhost:5173/preview/ (git에는 안 들어감).
  - 사용자가 미리 보기를 보고 "올려 줘"라고 하면 그때 브랜치를 main에 합쳐 실제 앱을 바꾼다.

## 체험하는 법
- PC: `python serve.py` → http://localhost:5173/docs/mockups/prototype.html (버전 목록 → 위쪽 막대에서 갤럭시 탭/아이폰 전환)
- 실제 기기: `python serve.py 5173 --lan` → 같은 와이파이에서 `http://PC의IP:5173/docs/mockups/prototype.html` — 휴대폰·태블릿에서는 틀 없이 앱처럼 꽉 차게 뜬다
- 기록은 그 브라우저에 저장된다. 처음부터 보려면 설정 › 처음 설정부터 다시.

## 핵심 흐름
처음 설정(시험 → 과목 → 교재) → "오늘부터 나눠서 시작" → 오늘 화면에 할 일이 들어감 → 체크 → 진도 막대가 채워지고 "통합사회 진도 47% → 51%"가 뜸 → 못 한 건 한 번에 정리하거나 남은 계획을 다시 나눔.
