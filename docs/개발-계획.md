## 2단계 · 구체화 — 각각 어떻게 보이고 어떻게 동작하나

### ① 시험 주기 (가장 중요)
- **시험 날이 지나면** 오늘 화면 맨 위에 한 줄만 뜬다: `2학기 중간고사 끝 · 결과 적기 · 다음 준비` (원칙 6: 그 상황일 때만 나타남)
- **결과 적기**
  - 과목별 점수 한 칸씩. 석차와 평균은 더 보기 안에 둔다.
  - 적은 점수는 그 과목 내신 기록의 "1차 시험" 칸에 바로 들어간다. 두 번 적지 않는다.
- **기록 고정**
  - 결과를 적는 순간 공부한 기록(진도 %, 계획 중 끝낸 비율, 미룬 횟수)을 그 시험에 묶어 둔다.
  - 그 뒤로 진도를 고쳐도 시험 리포트는 바뀌지 않는다.
- **다음 준비**: 입력은 쪽수만 받는다(원칙 3).
  - 다음 시험 이름과 날짜를 미리 채운다. 중간고사 다음은 기말고사.
  - 과목, 교재, 공부 순서는 지난 시험 것을 그대로 가져온다.
  - 각 교재는 지난 범위 다음 쪽부터 시작하도록 기본값을 넣는다. 예: 자습서 61쪽~
- **못 끝낸 할 일**: 지난 시험 기록으로 넘기고, 오늘 화면에서는 치운다.
- **시험이 없는 기간**
  - '시험' 대신 **'끝낼 날'**을 정한다. 자료 구조는 시험과 똑같고, 종류만 '목표'로 둔다.
  - 성적 비교가 없다는 것만 다르다.
- 모의고사는 결과만 적는다. 계획 대상이 아니다. v3 방식을 유지한다.

### ② 지문별로 보기
- 과목의 단계 고치기 안에 `세는 방법: 쪽 / 지문` 선택을 둔다. 기본은 쪽이고, 겉에는 보이지 않는다.
- 지문을 고르면 지문 수(예: 12)를 적는다.
  - 진도 칸이 **지문 × 회독** 격자로 바뀐다.
  - 칸을 누르면 채워진다.
- 날짜별로 나누는 것도 지문 단위로 한다. 할 일 예: `지문 3–5 · 2회독`
- 진도 % = 채운 칸 ÷ 전체 칸

### ③ 틀린 이유·회고
- 시험 리포트에서 과목을 누르면(층 1) 틀린 이유 5개(개념 / 실수 / 시간 부족 / 안 한 범위 / 처음 보는 유형)가 개수 칸으로 나온다. 적지 않아도 된다.
- '안 한 범위'를 누르면 시험 당시 끝나지 않았던 단계가 함께 보인다.
- 모의고사는 틀린 문항 번호를 누르고, 번호마다 이유를 고른다. 선택 입력이다.
- 리포트 맨 아래에는 한 줄 회고 칸을 둔다.
- 쌓인 이유는 성적 탭 › 더 보기에서 시험별·과목별 비율로 본다(층 2).

### ④ 할 일 필드·보기
- **중요도(3단계)**
  - 할 일 › 더 보기 안에서 정한다.
  - 줄에는 작은 표시 하나만 붙는다. 정하지 않으면 아무 표시도 없다.
- **반복 횟수**
  - 예: 3번 → 체크할 때마다 1/3 → 2/3 → 3/3.
  - 이미 있는 부분 체크 그림을 그대로 쓴다.
- **보기 방식**
  - 오늘 › … 메뉴에서 `과목별 / 마감순 / 시간순` 중에 고른다.
  - 시간순은 더 보기에서 '시작 시각'을 적은 것만 시각 순서로 놓고, 나머지는 뒤에 둔다.

### ⑤ 성적 구조
- **과목 설정**
  - 학점을 적는다.
  - '성취도만 나옴'을 켜고 끌 수 있다. 켜면 평균 등급 계산에서 빠진다.
  - 평가 구성은 기본 틀(1차 30 / 2차 30 / 수행 40)에서 고친다.
- 반영비율 합이 100이 아니면 `합계 90%`처럼 **사실만** 표시한다. 경고 문구는 쓰지 않는다.
- 과목 진도 화면 숫자 아래에 한 줄을 둔다: `아직 점수가 안 나온 비중 70%`

### ⑥ 실제 앱으로 옮기기
- **그대로 쓰는 것**: 화면 엔진(`src/lib`), 계산(`src/core`), 기기 저장·동기화 틀(`src/data/db.js`, `src/sync`)
- **새로 바꾸는 것**: 화면·자료 구조는 v3로 교체한다.
  - 시험 → 과목 → 교재 → 단계 → 할 일
  - 할 일은 모두 어느 시험(또는 목표)에 속한다.
- **테스트로 옮기는 계산**
  - 날짜별 나누기: 합계가 남은 분량과 같아야 한다.
  - 체크하면 진도가 오른다.
  - 일부만 했을 때 남은 쪽이 넘어간다.
  - "쎈 p.20-35" 연결, 되돌리기, 시험 주기 전환
- 화면 설정(디자인, 글자, 태블릿 배치)은 기기마다 따로 저장한다(문서 4-1).

### ⑦ 설치·오프라인
- 필요한 것: 앱 정보 파일, 오프라인 저장(`sw.js`), 아이콘(Python으로 PNG 생성)
- 아이폰: Safari › 공유 › 홈 화면에 추가. 갤럭시: 삼성 인터넷 › 메뉴 › 홈 화면에 추가. 둘 다 안내 문서로 만든다.

### ⑧ 로그인·동기화
- Supabase에 필요한 것: 테이블 만드는 SQL, 로그인 화면, 두 기기 동시 수정 처리(마지막 수정이 이김), 사진 저장소
- 동기화 상태는 설정 안에만 작게 보인다. 겉에는 내놓지 않는다.

| Supabase 무료 프로젝트는 1주일 안 쓰면 멈춤 | 방학에 오래 안 쓰면 동기화가 끊김 | 기기 저장이 기본이라 앱은 계속 된다. 대시보드에서 다시 켜는 법을 안내한다 |
| 아이폰 Safari는 홈 화면에 추가하지 않으면 7일 뒤 저장 자료를 지울 수 있음 | 자료 손실 위험 | 홈 화면 설치를 안내하고, 동기화 전까지는 파일 백업(내보내기/가져오기)을 먼저 넣는다 |
| 제가 실제 기기를 만질 수 없음 | 터치감과 삼성 인터넷의 특이점은 직접 확인 못 함 | 화면 크기 흉내로 먼저 점검한다. 단계마다 사용자가 기기에서 확인하는 시간을 둔다 |
| 열품타 공식 내보내기 방식을 모름 | 추측으로 만들면 안 됨 | 보류. 사용자가 방식을 알려 주면 그때 설계한다 |
| 사진 동기화는 용량이 큼 | 무료 한도 | 사진은 줄여서 올린다. 처음에는 기기 저장만 하고, 동기화는 마지막에 붙인다 |

**뺄 것 / 미룰 것**
- 고정 일정(학원 요일)을 따로 입력받지 않는다. 공부 가능 시간이 이미 그걸 뺀 값이기 때문이다. 특정 날만 시간을 바꾸는 기능만 둔다.
- 레이더 차트는 넣지 않는다. 비교할 기준 자료가 없어서 판단 없이 보여 주기 어렵다. 막대와 선 그래프만 쓴다.

## 4단계 · 다듬기 — 순서와 확인 지점

**새 기능마다 확인할 원칙 체크리스트**
1. 처음 화면에 늘어난 게 있나? → 없어야 한다. 그 상황일 때만 뜨는 한 줄은 예외.
2. 매일 하는 동작이 여전히 한 번 탭인가?
3. 새 입력이 생겼나? → 기본값이나 지난 기록으로 대신 채울 수 있나?
4. 어떤 설정 조합에서도 보기 좋은가? (디자인 3 × 밝게·어둡게 × 휴대폰·태블릿 전수 점검)
5. 예측·추천·칭찬·게임 요소 문구가 없나?
6. 처음 보는 사람이 모를 단어가 없나? 괄호 설명 없이 읽히나?

**순서** — 싸게 고칠 수 있는 것부터, 되돌리기 어려운 것은 나중에

| 차례 | 내용 | 끝났다고 보는 기준 | 사용자 확인 |
|---|---|---|---|
| **A** | 프로토타입에 ①~⑤ 추가 → **v4로 완료 (2026-09-30)** | 시험 하나를 처음 설정부터 결과 적기, 다음 시험 준비까지 끊김 없이 해 볼 수 있음. 전수 점검 오류 0 | ✅ 기기에서 눌러 보고 의견 |
| **B** | 실제 앱으로 옮기기 (⑥) + 파일 백업 → **완료 (2026-09-30)** | 새로 고쳐도 자료가 남음. 계산 테스트 전부 통과. v5와 화면이 같음 | ✅ PC와 같은 와이파이 기기에서 확인 |
| **C** | 설치·오프라인 (⑦) → **완료** (서버를 끄고 열리는 것 확인) | 비행기 모드에서 열리고 체크됨 | ⚠️ 호스팅 계정 필요 |
| **D** | 로그인·동기화 (⑧) → **완료** (가짜 서버로 두 기기 시험) | 탭에서 체크한 게 아이폰에 나타남. 동시에 고쳐도 자료가 안 사라짐 | ⚠️ Supabase 프로젝트 필요 |
| **E** | 1주일 실제 사용 → 고치기 | 사용자가 말한 불편 목록이 비어 있음 | ✅ |
| F | 열품타 (보류) | — | ⚠️ 방식 확인 필요 |

A를 먼저 하는 이유: 프로토타입은 고치기 싸다. 시험 주기처럼 자료 구조를 바꾸는 설계는 실제 앱으로 옮기기 전에 확정해야 다시 옮기는 일이 없다.

## 2. 구체화 (실제 앱 저장 방식)
- 화면 코드는 프로토타입과 같은 '한 덩어리 자료'를 쓴다. 저장할 때만 **바뀐 레코드만** 골라 IndexedDB 표에 쓴다.
  - 과목 / 할 일 / 지난 시험 / 학기 / 설정(시험·공부 시간) 다섯 표
- 이렇게 하면 화면 코드를 거의 그대로 옮기고도, 동기화는 레코드 단위(나중에 고친 쪽이 이김)로 된다.
- 기기마다 다른 것(디자인, 글자 크기, 태블릿 배치)은 이 기기에만 저장한다 (문서 4-1).
- 다른 기기에서 온 변경은 바뀐 레코드만 바꿔 끼운다.

## 3. 현실화
| 막히는 것 | 대응 |
|---|---|
| Supabase 계정이 없어 실제 서버로 시험 못 함 | **가짜 Supabase 서버**(Python, 같은 주소 규칙)를 만들어 두 '기기'(localhost와 127.0.0.1은 저장 공간이 따로)로 동기화를 시험한다 |
| 호스팅 계정이 없음 | 오프라인·설치는 localhost에서 시험 (서비스 워커는 localhost에서 동작). 올리는 법은 안내 문서로 |
| 실제 기기 터치 | 화면 크기 흉내 + 전수 점검. 기기 확인은 사용자 몫으로 남긴다 |
