## 2단계 · 구체화 — 각각 어떻게 보이고 어떻게 동작하나

### ① 시험 주기 (가장 중요)
- **시험 날이 지나면** 오늘 화면 맨 위에 한 줄만 뜬다: `2학기 중간고사 끝 · 결과 적기 · 다음 준비` (원칙 6: 그 상황일 때만 나타남)
- **결과 적기**
  - 과목별 점수 한 칸씩. 석차와 평균은 더 보기 안에 둔다.
  - 적은 점수는 그 과목 내신 기록의 "1차 시험" 칸에 바로 들어간다. 두 번 적지 않는다.
- **기록 고정**
  - 결과를 적는 순간 공부한 기록(진도 %, 계획 중 끝낸 비율, 미룬 횟수)을 그 시험에 묶어 둔다.
  - 그 뒤로 진도를 고쳐도 시험 리포트는 바뀌지 않는다.
- **다음 준비**: 입력은 쪽수만 받는다(원칙 3).
  - 다음 시험 이름과 날짜를 미리 채운다. 중간고사 다음은 기말고사.
  - 과목, 교재, 공부 순서는 지난 시험 것을 그대로 가져온다.
  - 각 교재는 지난 범위 다음 쪽부터 시작하도록 기본값을 넣는다. 예: 자습서 61쪽~
- **못 끝낸 할 일**: 지난 시험 기록으로 넘기고, 오늘 화면에서는 치운다.
- **시험이 없는 기간**
  - '시험' 대신 **'끝낼 날'**을 정한다. 자료 구조는 시험과 똑같고, 종류만 '목표'로 둔다.
  - 성적 비교가 없다는 것만 다르다.
- 모의고사는 결과만 적는다. 계획 대상이 아니다. v3 방식을 유지한다.

### ② 지문별로 보기
- 과목의 단계 고치기 안에 `세는 방법: 쪽 / 지문` 선택을 둔다. 기본은 쪽이고, 겉에는 보이지 않는다.
- 지문을 고르면 지문 수(예: 12)를 적는다.
  - 진도 칸이 **지문 × 회독** 격자로 바뀐다.
  - 칸을 누르면 채워진다.
- 날짜별로 나누는 것도 지문 단위로 한다. 할 일 예: `지문 3–5 · 2회독`
- 진도 % = 채운 칸 ÷ 전체 칸

### ③ 틀린 이유·회고
- 시험 리포트에서 과목을 누르면(층 1) 틀린 이유 5개(개념 / 실수 / 시간 부족 / 안 한 범위 / 처음 보는 유형)가 개수 칸으로 나온다. 적지 않아도 된다.
- '안 한 범위'를 누르면 시험 당시 끝나지 않았던 단계가 함께 보인다.
- 모의고사는 틀린 문항 번호를 누르고, 번호마다 이유를 고른다. 선택 입력이다.
- 리포트 맨 아래에는 한 줄 회고 칸을 둔다.
- 쌓인 이유는 성적 탭 › 더 보기에서 시험별·과목별 비율로 본다(층 2).

### ④ 할 일 필드·보기
- **중요도(3단계)**
  - 할 일 › 더 보기 안에서 정한다.
  - 줄에는 작은 표시 하나만 붙는다. 정하지 않으면 아무 표시도 없다.
- **반복 횟수**
  - 예: 3번 → 체크할 때마다 1/3 → 2/3 → 3/3.
  - 이미 있는 부분 체크 그림을 그대로 쓴다.
- **보기 방식**
  - 오늘 › … 메뉴에서 `과목별 / 마감순 / 시간순` 중에 고른다.
  - 시간순은 더 보기에서 '시작 시각'을 적은 것만 시각 순서로 놓고, 나머지는 뒤에 둔다.

### ⑤ 성적 구조
- **과목 설정**
  - 학점을 적는다.
  - '성취도만 나옴'을 켜고 끌 수 있다. 켜면 평균 등급 계산에서 빠진다.
  - 평가 구성은 기본 틀(1차 30 / 2차 30 / 수행 40)에서 고친다.
- 반영비율 합이 100이 아니면 `합계 90%`처럼 **사실만** 표시한다. 경고 문구는 쓰지 않는다.
- 과목 진도 화면 숫자 아래에 한 줄을 둔다: `아직 점수가 안 나온 비중 70%`

### ⑥ 실제 앱으로 옮기기
- **그대로 쓰는 것**: 화면 엔진(`src/lib`), 계산(`src/core`), 기기 저장·동기화 틀(`src/data/db.js`, `src/sync`)
- **새로 바꾸는 것**: 화면·자료 구조는 v3로 교체한다.
  - 시험 → 과목 → 교재 → 단계 → 할 일
  - 할 일은 모두 어느 시험(또는 목표)에 속한다.
- **테스트로 옮기는 계산**
  - 날짜별 나누기: 합계가 남은 분량과 같아야 한다.
  - 체크하면 진도가 오른다.
  - 일부만 했을 때 남은 쪽이 넘어간다.
  - "쎈 p.20-35" 연결, 되돌리기, 시험 주기 전환
- 화면 설정(디자인, 글자, 태블릿 배치)은 기기마다 따로 저장한다(문서 4-1).

### ⑦ 설치·오프라인
- 필요한 것: 앱 정보 파일, 오프라인 저장(`sw.js`), 아이콘(Python으로 PNG 생성)
- 아이폰: Safari › 공유 › 홈 화면에 추가. 갤럭시: 삼성 인터넷 › 메뉴 › 홈 화면에 추가. 둘 다 안내 문서로 만든다.

### ⑧ 로그인·동기화
- Supabase에 필요한 것: 테이블 만드는 SQL, 로그인 화면, 두 기기 동시 수정 처리(마지막 수정이 이김), 사진 저장소
- 동기화 상태는 설정 안에만 작게 보인다. 겉에는 내놓지 않는다.

| Supabase 무료 프로젝트는 1주일 안 쓰면 멈춤 | 방학에 오래 안 쓰면 동기화가 끊김 | 기기 저장이 기본이라 앱은 계속 된다. 대시보드에서 다시 켜는 법을 안내한다 |
| 아이폰 Safari는 홈 화면에 추가하지 않으면 7일 뒤 저장 자료를 지울 수 있음 | 자료 손실 위험 | 홈 화면 설치를 안내하고, 동기화 전까지는 파일 백업(내보내기/가져오기)을 먼저 넣는다 |
| 제가 실제 기기를 만질 수 없음 | 터치감과 삼성 인터넷의 특이점은 직접 확인 못 함 | 화면 크기 흉내로 먼저 점검한다. 단계마다 사용자가 기기에서 확인하는 시간을 둔다 |
| 열품타 공식 내보내기 방식을 모름 | 추측으로 만들면 안 됨 | 보류. 사용자가 방식을 알려 주면 그때 설계한다 |
| 사진 동기화는 용량이 큼 | 무료 한도 | 사진은 줄여서 올린다. 처음에는 기기 저장만 하고, 동기화는 마지막에 붙인다 |

**뺄 것 / 미룰 것**
- 고정 일정(학원 요일)을 따로 입력받지 않는다. 공부 가능 시간이 이미 그걸 뺀 값이기 때문이다. 특정 날만 시간을 바꾸는 기능만 둔다.
- 레이더 차트는 넣지 않는다. 비교할 기준 자료가 없어서 판단 없이 보여 주기 어렵다. 막대와 선 그래프만 쓴다.

## 4단계 · 다듬기 — 순서와 확인 지점

**새 기능마다 확인할 원칙 체크리스트**
1. 처음 화면에 늘어난 게 있나? → 없어야 한다. 그 상황일 때만 뜨는 한 줄은 예외.
2. 매일 하는 동작이 여전히 한 번 탭인가?
3. 새 입력이 생겼나? → 기본값이나 지난 기록으로 대신 채울 수 있나?
4. 어떤 설정 조합에서도 보기 좋은가? (디자인 3 × 밝게·어둡게 × 휴대폰·태블릿 전수 점검)
5. 예측·추천·칭찬·게임 요소 문구가 없나?
6. 처음 보는 사람이 모를 단어가 없나? 괄호 설명 없이 읽히나?

**순서** — 싸게 고칠 수 있는 것부터, 되돌리기 어려운 것은 나중에

| 차례 | 내용 | 끝났다고 보는 기준 | 사용자 확인 |
|---|---|---|---|
| **A** | 프로토타입에 ①~⑤ 추가 → **v4로 완료 (2026-09-30)** | 시험 하나를 처음 설정부터 결과 적기, 다음 시험 준비까지 끊김 없이 해 볼 수 있음. 전수 점검 오류 0 | ✅ 기기에서 눌러 보고 의견 |
| **B** | 실제 앱으로 옮기기 (⑥) + 파일 백업 → **완료 (2026-09-30)** | 새로 고쳐도 자료가 남음. 계산 테스트 전부 통과. v5와 화면이 같음 | ✅ PC와 같은 와이파이 기기에서 확인 |
| **C** | 설치·오프라인 (⑦) → **완료** (서버를 끄고 열리는 것 확인) | 비행기 모드에서 열리고 체크됨 | ⚠️ 호스팅 계정 필요 |
| **D** | 로그인·동기화 (⑧) → **완료** (가짜 서버로 두 기기 시험) | 탭에서 체크한 게 아이폰에 나타남. 동시에 고쳐도 자료가 안 사라짐 | ⚠️ Supabase 프로젝트 필요 |
| **E** | 1주일 실제 사용 → 고치기 | 사용자가 말한 불편 목록이 비어 있음 | ✅ |
| F | 열품타 (보류) | — | ⚠️ 방식 확인 필요 |

A를 먼저 하는 이유: 프로토타입은 고치기 싸다. 시험 주기처럼 자료 구조를 바꾸는 설계는 실제 앱으로 옮기기 전에 확정해야 다시 옮기는 일이 없다.

## 2. 구체화 (실제 앱 저장 방식)
- 화면 코드는 프로토타입과 같은 '한 덩어리 자료'를 쓴다. 저장할 때만 **바뀐 레코드만** 골라 IndexedDB 표에 쓴다.
  - 과목 / 할 일 / 지난 시험 / 학기 / 설정(시험·공부 시간) 다섯 표
- 이렇게 하면 화면 코드를 거의 그대로 옮기고도, 동기화는 레코드 단위(나중에 고친 쪽이 이김)로 된다.
- 기기마다 다른 것(디자인, 글자 크기, 태블릿 배치)은 이 기기에만 저장한다 (문서 4-1).
- 다른 기기에서 온 변경은 바뀐 레코드만 바꿔 끼운다.

## 2. 구체화

### ① 반복하는 할 일
- **켜는 곳**: 할 일 › 더 보기 › `반복: 안 함 / 매일 / 요일마다` (요일마다면 요일 칩). 가끔 하는 일이라 층 2(원칙 2).
- **동작**: 켜면 '반복 규칙'이 생기고, 오늘부터 **2주 앞까지** 그 요일마다 같은 할 일이 들어간다. 날이 지나면 2주 앞까지 계속 채운다.
- **바꾸기**: 반복하는 일의 이름·예상 시간·중요도·시작 시각·횟수를 바꾸면 **그 뒤 날짜의 반복에도** 반영된다(시트에 한 줄로 알림). 메모·사진·마감일·걸린 시간은 그날 것만.
- **한 번만 빼기**: 그날 것을 삭제하면 그날만 빠지고, 다시 생기지 않는다.
- **그만하기**: `반복 그만하기` → 내일부터의 반복을 치운다(되돌리기 가능). 오늘 것과 지난 기록은 남는다.
- **못 한 날**: 반복하는 일은 밀리지 않는다. 지난 날 못 한 것은 '지난 날 못 끝낸 일'에 넣지 않고 그날 기록(돌아보기의 '못 한 일')으로만 남는다. 매일 하는 일이 쌓이면 플래너가 버려지기 때문(문서 3-B 하루 마감 근거).
- **모아 보기**: 오늘 › … 메뉴에 `반복하는 일` (규칙이 있을 때만) → 목록(이름·요일·과목), 그만하기.
- 겉(할 일 줄)에는 표시를 붙이지 않는다.

### ② 마감이 가까운 일
- 조건: 안 끝낸 일 중 **마감일이 오늘~3일 뒤**이고 **오늘 목록에 없는 것**.
- 오늘 화면 맨 위에 한 줄: `마감이 가까운 일 2개 · 수행평가 보고서 10/3(금)` → 누르면 목록 시트(마감일, 잡아 둔 날, `오늘 하기`).
- 달력: 마감일 칸에 `마감` 표시.
- 설정 › 보일 것에서 끌 수 있다(기본 켬).

### ③ 돌아보기 기간
- 돌아보기 위에 `한 주 / 시험 준비 전체` (시험이나 끝낼 날이 있을 때만). 전체 = 시험 준비를 시작한 날 ~ 오늘.
- 숫자·표·이유·예상 대비 시간은 같은 계산을 기간만 바꿔서.

### ④ 나눌 때 시간 먼저 빼기
- 날마다 나누는 무게 = 공부 가능 시간 − (그날 직접 넣은 일 + 반복하는 일 예상 시간). 0보다 작으면 0.
- 모든 날이 0이면 원래 공부 가능 시간으로 나눈다(아무것도 안 들어가는 일은 없게).
- 나눠 보기의 날마다 시간 표시에도 아직 안 채운 반복하는 일(2주 뒤)을 더한다.

### ⑤ 백업한 날
- 설정 › 자료 › 파일로 내보내기 아래 작은 글씨: `마지막 백업 9월 20일` / `아직 안 함`. 기기마다 따로.

- 사라지는 창의 복사본에 **스크롤 위치와 적던 글자**를 그대로 옮김 (안 그러면 사라지는 순간 맨 위로 튀어 보임).
- 사라지는 복사본은 화면 읽기 프로그램이 읽지 않게, 누를 수 없게.
- 창을 빠르게 닫았다 다시 열면 배경이 두 겹으로 어두워지는 순간이 생김 → 새로 열 때 남은 복사본을 바로 치움.
- 화면에 처음 들어올 때(탭을 옮겨 왔을 때) 끝낸 일의 동그라미가 한꺼번에 채워지는 움직임이 나오면 안 됨 → **내가 방금 누른 것만** 움직임.

# 5차 — 베타 1.0: 실제로 써 보고 막힌 곳 · 알맹이 채우기 (2026-10-04 ~ )

## 1. 계획짜기 — 코드를 한 줄씩 다시 읽고 찾은 원인

**A. 숫자 입력 (가장 급함 — 기록이 틀리게 들어감)**

| 항목 | 판단 | 이유 |
|---|---|---|
| 숫자 칸 | **치는 동안은 그대로 두고, 다 친 뒤(칸을 떠날 때·완료) 확인.** 범위 밖이면 가까운 값으로 맞추고 칸 아래 한 줄로 알려 줌 | 말없이 무시하는 게 가장 나쁨. 보이는 숫자 = 저장된 숫자 |
| 교재 시작 쪽 > 끝 쪽 | 끝 쪽을 **같은 길이만큼 함께 옮김** (1–60 → 70을 치면 70–129, 바로 보임) | 범위를 바꿀 때 보통 시작부터 친다. 막지 말고 따라가기 |
| 교재 범위를 바꾸면 | 그 교재를 쓰는 **단계 범위도 함께**, 이미 한 진도는 범위 안이면 그대로 | 고쳤는데 안 바뀌는 게 버그의 정체 |
| 단위 | **교재마다** 쪽 · 지문 · 문제 · 강 · 회 · 단원(1-1, 1-2… 직접 이름) | 과목 하나에 여러 종류 교재가 섞인다 |
| 칸 채우기 | 쪽은 '어디까지'(읽는 순서대로), 나머지는 **칸**(골라서 채움) | 쪽은 순서대로 읽고, 지문·문제·단원은 건너뛰며 본다 |
| 단위가 섞인 과목의 % | 같은 단위면 개수 그대로, 섞이면 **걸리는 시간으로** 무게를 줌 | 1쪽과 1강을 같은 하나로 세면 틀린 숫자 |
| 단위를 바꾸면 | 쪽 ↔ 번호는 한 만큼 옮겨 줌, 단원 목록으로 바꿀 때만 처음부터 (미리 알려 줌) | 적어 둔 진도를 함부로 지우지 않기 |
| 창 끌어내리기 | 휴대폰(손가락)은 **기기 스크롤로** 움직이게 → 120Hz·관성·튕김이 아이폰 기본 그대로 | 계산으로 따라가게 하는 한 기본 창처럼 부드러울 수 없음 |
| 확대 | 두 번 누르기·두 손가락·입력칸 확대 모두 끔. 대신 설정의 글자 크기 | 앱은 확대되지 않는다. 글자 크기는 설정에 있다 |
| 아래 막대 | 아이폰은 **떠 있는 유리 막대**(리퀴드 글래스), 나머지는 지금 디자인. 설정에서 바꿀 수 있게 | 사용자 요청 + 기기마다 어울리는 것 |
| ＋ 단추 | 유리 막대에서는 **막대와 같은 줄 오른쪽**의 동그란 단추. 기본 막대에서는 막대 바로 위 | '혼자 높이 떠 있음'을 없앤다 |
| 화면 옮기기 | 옛 화면이 흐려지는 동안 새 화면이 나타남(**겹쳐 바뀜**) → 빈 순간이 없다 | 깜빡임의 정체가 빈 순간 |
| 설정 | 애플 설정처럼: 맨 위 계정, 그 아래 **화면** 묶음을 앞에. 줄마다 아이콘, 오른쪽에 지금 값 | 설정에 들어오는 이유는 '내 화면 바꾸기' |
| 새 화면 설정 | 강조 색 · 굵은 글씨 · 탭 막대 모양·이름 · 앱을 열면 볼 화면 · 끝낸 일(그대로·아래로·숨기기) · D-day 모양 · 할 일 줄에 예상 시간 · 진도를 %/분량으로 · 주 시작 요일 · 시간 표시(24시간/오전·오후) · 진동(되는 기기만) | 모두 고르는 즉시 보이고, 무엇을 골라도 어울리게 미리 설계 |
| 진도 막대 | **채움만**: 한 칸 = 한 단계, 한 만큼 진하게, 안 한 곳은 옅은 같은 색. 밑줄·테두리 없음 | 막대는 한눈에 '얼마나'만 |

## 3. 추가 — 검토하다 새로 나온 것
- 할 일 › 일부만 했어요: 칸 단위 교재는 '몇 번까지' 대신 **한 칸을 골라 누르기** (건너뛴 번호도 맞게).
- 할 일 추가: 과목을 고르면 **"이어서: 자습서 p.31–40"** 한 줄 → 누르면 진도에 이어지는 할 일. 마법 같은 입력법을 몰라도 되게.
- 단원 목록 만들기: "큰 단원 4개 × 작은 단원 3개" → 1-1 … 4-3. 직접 적기도("춘향전, 관동별곡").
- 진도·할 일에서 단원 이름 그대로 보이기 ("1-1 ~ 1-3", "Lesson 2").
- 설정 안쪽으로 들어갈 때 오른쪽에서 밀려 들어오고, 뒤로 가면 왼쪽으로 (아이폰 설정처럼).
- 지금 탭을 한 번 더 누르면 맨 위로 (아이폰 기본).
- 길게 누르면 뜨는 글자 고르기·확대경을 단추에서는 끔 (앱처럼).
- 설정 › 정보: 버전 '베타 1.0', 쓰는 법(체크·밀기·일부만·칸 채우기) 짧게.

## 4. 검토 — 버그 날 만한 곳
- 예전 기록(과목에 '지문으로 세기'만 있던 것)이 새 단위로 그대로 보이는가 — 기록은 고쳐 쓰지 않고 읽을 때 해석.
- 다른 기기가 아직 옛 버전일 때: 칸 기록(marks)은 옛 버전도 읽는다. 단위 이름만 '쪽'으로 보일 수 있음 (두 기기 모두 새 버전이면 해결).
- 나누기(시간 무게): 단위가 하나뿐이면 지금과 **똑같이** 나뉘어야 함 → 테스트로 고정.
- 숫자 칸: 다시 그려져도 치던 글자가 지워지지 않게(칸을 보고 있는 동안은 화면이 값을 덮어쓰지 않음).
- 기기 스크롤 창: 닫으려고 끝까지 내렸을 때 사라지는 움직임이 다시 나타나지 않게, 키보드가 올라와도 창이 닫히지 않게, 창 안 목록 스크롤과 닫기 끌기가 섞이지 않게.
- 유리 막대가 내용을 덮는 만큼 아래 여백, 알림·＋ 위치. 전수 점검의 '못 누름'이 막대 뒤 내용을 잘못 세지 않게.
- 겹쳐 바뀜: 사라지는 복사본이 남지 않음, 누를 수 없음, 스크롤 위치 그대로 (움직임 체크리스트 M·N 추가).

## 5. 최종 검토 — 이것이 다 맞아야 끝
- 숫자 칸 전부: 여러 자리 숫자를 칠 수 있고, 범위 밖이면 알려 주고, 보이는 값 = 저장된 값.
- 영어 교과서를 1-1 … 4-3 단원으로 넣고 칸 채우기 → 할 일·진도·나누기·돌아보기까지 맞게.
- 예전 '지문으로 세기' 과목(예시의 공통영어) 그대로.
- 테스트 통과 + 화면 전수 점검(넘침·꺾임·못 누름 0) + 움직임 점검 통과.
- 아이폰에서만 확인할 것(사용자): 창 끌어내리기 느낌, 유리 막대, 확대 안 됨.

## 6. 실행 순서
① 단위 모델(교재마다) + 예전 기록 해석 + 계산(%, 나누기 무게, 범위 고치기) + 테스트 → ② 숫자 칸 하나로(NumField) 바꾸고 모든 숫자·날짜 칸 교체 → ③ 진도 화면(교재 편집·칸 채우기·막대) → ④ 오늘(할 일 줄·일부만·이어서 추가) → ⑤ 창(기기 스크롤·밀어 올라오기) → ⑥ 유리 막대·＋·막대 높이·맨 위로 → ⑦ 겹쳐 바뀜 → ⑧ 설정 다시 짜기 + 새 화면 설정 → ⑨ 확대 끄기 → ⑩ 정보·버전·문서 → ⑪ 브라우저로 화면마다 보고 고치기 → ⑫ 점검·미리 보기

- 설정에서 **뒤로 가면 앞 쪽의 스크롤 자리를 기억**해 그 자리로 (아이폰 설정처럼). 지금은 늘 맨 위.
- 막대를 밀다가 손가락이 '설정' 칸까지 가도 탭은 세 개뿐 → 마지막 탭에서 고무줄처럼 버팀(설정 창이 갑자기 열리지 않게).
- 밀기가 끝난 뒤 손가락을 뗀 자리의 단추가 한 번 더 눌리지 않게(누르기 한 번 = 한 동작).
- 움직임을 끈 사람: 밀기는 손가락을 따라가되(움직임이 아니라 손의 위치) 놓으면 바로 그 탭.
- 움직임 체크리스트에 Q(용수철 렌즈)·R(막대 밀기) 추가, N(창 열기)·P(설정 쪽)·C1(창→창) 고침.

## 4. 검토 — 버그 날 만한 곳
- 창: 스크롤 상자를 움직이는 동안 손가락으로 잡아도 이상 없나, 닫는 복사본도 상자째 내려가나, 창→창에서 앞 창 복사본이 남지 않나(빠르게 10번), 태블릿·PC 창은 그대로인가.
- 설정 쪽: 복사본이 창 밖으로 삐져나오지 않나(창 안에 가둠), 빠르게 여러 번 눌러도 복사본이 쌓이지 않나, 다 끝나면 붙였던 모양(위치·배경·높이)을 모두 걷어 내나, 어두운 화면에서도 배경색이 맞나.
- 막대 밀기: 누르기만 하면 지금처럼 탭이 바뀜, 세로로 움직이면 무시, 손가락이 막대 밖으로 나가도 놓을 때까지 따라감, 취소(pointercancel)되면 제자리로, 탭 이름을 끈 막대(낮은 막대)에서도 맞음.
- 시작 이미지: 미리 보기 폴더에서도 경로가 맞는가(icons/ 함께 복사됨), 서비스 워커 목록.
- 이미 설치한 홈 화면 앱은 시작 이미지를 바로 못 받을 수 있음 → 사용자에게 정직하게(홈 화면에서 지우고 다시 추가하면 확실).

## 5. 최종 검토 — 이것이 다 맞아야 끝
- 노드 테스트 전부 + 움직임 점검 4단계 전부 + 화면 전수 점검 0.
- 브라우저(휴대폰 390×844, 손가락)로: 창 열기·닫기·창→창·설정 쪽 넘기기·뒤로를 장면마다 찍어 **두 겹 글자·튐이 없는지** 눈으로 확인. 막대 탭·밀기.
- 아이폰에서만 확인할 것(사용자): 창이 위로 튀지 않는지, 방울이 미끄러지는 느낌, 밀기, 시작할 때 흰 화면.

## 6. 실행 순서
① 창 열기·닫기(스크롤 상자째) → ② 창→창 → ③ 설정 쪽 넘기기 + 스크롤 기억 → ④ 막대 용수철 + 밀기 → ⑤ 숫자 옆 말(V6·V7)·계정 카드·알림 → ⑥ 시작 이미지 → ⑦ 브라우저로 장면마다 보고 고치기 → ⑧ 테스트·점검 → ⑨ 문서·미리 보기

## 3. 추가 — 검토하다 새로 나온 것
- 디자인 규칙 문서(docs/디자인-규칙.md): 읽은 글(애플 HIG·리퀴드 글래스, 디터 람스 10원칙, Refactoring UI, Laws of UX — 피츠·힉, 머티리얼 모션)에서 뽑은 규칙 → 간격 4의 배수, 글자 4단계, 색은 강조 하나, 단추 3종, 누르는 칸 44px 이상, 주 행동은 엄지 닿는 아래.
- 예전 기록 그대로: 예전 테마(paper·crisp·soft)·강조 색·속도 값은 읽을 때 새 값으로 바꿔 읽는다.
- 로그인한 계정에 이미 기록이 있으면 처음 설정을 건너뛴다(다른 기기에서 쓰던 기록).

## 4. 검토 — 버그 날 만한 곳
- 테마 이름이 바뀌어도 예전 `[data-theme='crisp']` 규칙이 새 화면에 걸리지 않게.
- 설정을 계정으로 맞출 때 두 기기가 동시에 바꾸면 나중 것이 이김(기록과 같음). 기기마다 다른 것(태블릿 칸 배치, 마지막 탭)은 빼기.
- 막대 누르기·밀기·스크롤이 섞이지 않게, 태블릿 막대가 내용 아래를 가리지 않게(아래 여백).
- 교과서 단원 칸: 단원 수가 적어(3~5) 하루 몫이 '단원 0.3개'가 되지 않게 — 단원이 적으면 날마다 한 단원씩.
- 처음 화면 로그인 중 실패·네트워크 없음.

## 5. 최종 검토 — 이것이 다 맞아야 끝
- 노드 테스트·움직임 점검·화면 전수 점검 통과. 브라우저로 처음 화면부터 끝까지 직접 해 보기(고1 → 2학기 과목 → 출판사 → 시작).
- 아이폰에서만 확인(사용자): 유리 막대, 창 잡아당기기, 설정 쪽 넘김, 처음 소개 움직임.

## 6. 실행 순서
① 규칙 문서 2개 → ② 움직임 정리(켜기/끄기, 가로 페이드, 창 아래 채우기, 시작 화면) → ③ 유리 막대(모든 기기) → ④ 테마·설정 동기화 → ⑤ 교육과정·교과서 자료 → ⑥ 처음 화면 → ⑦ 설정 다시 짜기 → ⑧ 문구 → ⑨ 점검·문서·미리 보기
