# 움직임(애니메이션) 버그 체크리스트

움직임을 새로 넣거나 고칠 때마다 이 목록을 **전부** 확인한다.
- **자동**: 브라우저에서 스크립트로 눌러 보고 결과를 센다. `document.getAnimations()`는 지금 도는 애니메이션 목록이다.
- **기기**: 갤럭시 탭(삼성 인터넷)과 아이폰(Safari)에서 손으로 확인한다.

움직임 설정 4단계(느긋하게·보통·빠르게·끄기) × 디자인 3 × 밝게·어둡게 × 휴대폰·태블릿에서 본다.

**자동 점검 돌리는 법**
- 화면 점검: 앱(`index.html`)을 연 브라우저 콘솔에서 `(await import('/tests/motion-check.js')).runAll()` → 네 단계 결과. 실패한 항목 이름이 번호(A1, B1…)로 나온다.
  - 기본은 '넘기기' 방식: 시간을 기다리지 않고 애니메이션을 끝까지 넘겨서 본다. 느린 기기나 가려진 창에서도 결과가 같다.
  - 실제 속도로 보려면 `run({ level: 'normal', fast: false })`. 창이 가려져 있거나 느리면 시간 때문에 틀리게 나올 수 있다.
- 설정 점검(E1·E2, 기기의 '동작 줄이기' 흉내): `powershell -File tools/node.ps1 tests/run-node.js`에 들어 있다.

**이번에 점검에서 잡은 것**
- 창에서 창으로 넘어갈 때 배경이 다시 어두워지는 깜빡임 → 배경은 그대로, 앞 창만 흐려지게.
- 닫자마자 다시 열면 배경이 두 겹 → 남은 복사본을 치우고 연다.
- 알림이 사라지는 중에 새 알림이 뜨면 두 개가 겹침 → 새 알림이 뜰 때 사라지던 것을 치운다.
- 작게 만든 '누르는 칸 넓히기'가 가로 스크롤을 만드는지 → 안 만듦 (창·목록 모두 확인).
- 점검 도구 자체의 실수(움직임이 시작되기 전에 넘겨 버림)도 고침 — 결과를 믿을 수 있게.

**4차에 잡은 것 (D4)**
- 3차에서 사라지는 복사본에 붙인 이름 `.ghost`가 처음 화면 단추 모양 `.btn.ghost`와 같아서, '예시로 먼저 둘러보기'·'다른 기기에서 쓰던 기록이 있어요'가 **아예 눌리지 않았다** (누를 수 없게 하는 규칙이 그 단추에도 걸림). 3차 점검은 예시를 불러온 뒤의 화면만 봐서 처음 화면을 놓쳤다.
- 고친 것: 이름을 `m-ghost`로. 다시 생기지 않게 ① 이름이 다른 파일에 안 쓰이는지 테스트 ② 전수 점검이 화면의 모든 단추 가운데를 실제로 눌러 봄.
