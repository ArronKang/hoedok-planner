# 설치와 동기화 안내

앱은 인터넷 주소(https://arronkang.github.io/hoedok-planner/)에 올려 두고, 휴대폰·태블릿에서 **홈 화면에 추가**해서 앱처럼 씁니다. 앱스토어는 필요 없어요.
두 기기가 같은 기록을 쓰려면 **Supabase**(무료) 프로젝트가 하나 있어야 해요. 혼자 쓰는 계정이라 한 번만 만들면 됩니다.

| 순서 | 할 일 | 누가 | 걸리는 시간 |
|---|---|---|---|
| 1 | 앱을 인터넷에 올리기 (GitHub Pages) | 끝남 | — |
| 2 | 기기에 설치 (홈 화면에 추가) | 기기마다 한 번 | 1분 |
| 3 | 동기화 서버 만들기 (Supabase) | 처음 한 번 | 5~10분 |
| 4 | 서버 주소·공개 키를 앱에 넣기 (`src/config.js`) | 처음 한 번 | 1분 |
| 5 | 두 기기에서 로그인 | 기기마다 한 번 | 1분 |

3~5를 안 하면 기록은 **그 기기에만** 저장됩니다. 설정 › 자료 › 파일로 내보내기로 옮길 수는 있어요.

---

## 2. 기기에 설치 (홈 화면에 추가)

앱 안에서도 안내해요: 브라우저로 열면 처음 화면과 오늘 화면에 **"홈 화면에 추가하면 앱처럼 열려요 · 방법"**, 설정에 **"홈 화면에 앱으로 추가"**가 보여요. 아이콘으로 열면 이 안내는 사라져요.

**갤럭시 (삼성 인터넷)**
1. 삼성 인터넷으로 주소를 엽니다 (카메라로 QR을 찍으면 삼성 인터넷으로 열려요).
2. 앱 안의 '방법'을 누르면 설치 창이 바로 뜨기도 해요. 안 뜨면 아래쪽 **메뉴(≡) › 현재 페이지 추가 › 홈 화면**
3. 홈 화면의 초록 아이콘 **회독 플래너**로 엽니다. 주소창 없이 꽉 차게 떠요.

**아이폰 (Safari)**
1. **Safari**로 주소를 엽니다.
2. 아래쪽 **공유 단추(□↑) › 홈 화면에 추가 › 추가**
3. 홈 화면의 아이콘으로 엽니다.
   - 아이콘으로 연 앱은 Safari와 **기록이 따로**예요. 처음 설정과 로그인은 **아이콘으로 연 앱에서** 하세요.
   - Safari에서만 쓰면 7일 넘게 안 열었을 때 기록이 지워질 수 있어요. 아이콘으로 쓰고, 동기화도 켜 두세요.

한 번 연 뒤에는 **인터넷이 없어도 열리고 체크도 돼요.** 동기화는 인터넷이 되면 저절로 맞춰집니다.

## 3. 동기화 서버 만들기 (Supabase, 처음 한 번)

1. https://supabase.com → **Start your project** → **Continue with GitHub** (GitHub 계정으로 가입)
2. **New project**
   - Name: `hoedok` (아무거나)
   - Database Password: **Generate a password** (앱에서는 안 쓰지만 적어 두세요)
   - Region: **Northeast Asia (Seoul)**
   - **Create new project** → 1~2분 기다립니다.
3. 왼쪽 **SQL Editor › New query** → 이 폴더의 `supabase/schema.sql` 내용을 **전부 붙여 넣고 Run** → "Success"
4. **내 계정 만들기**: 왼쪽 **Authentication › Users › Add user › Create new user**
   - 이메일, 비밀번호(6자 이상)를 넣고 **Auto Confirm User**를 켠 채로 **Create user**
   - 이 이메일·비밀번호로 앱에서 로그인해요.
5. **다른 사람이 가입하지 못하게**: **Authentication › Sign In / Providers**(또는 Settings) › **Allow new users to sign up**을 끄고 **Save**
   - 혼자 쓰는 계정이라 새 가입이 필요 없어요. 앱 주소를 아는 사람이 계정을 만들어 무료 용량을 쓰는 것을 막아요.
6. **Project Settings › API Keys**(또는 Data API)에서 두 값을 복사합니다.
   - **Project URL**: `https://xxxx.supabase.co`
   - **Publishable key** (`sb_publishable_…`) 또는 예전 이름 **anon public** 키
   - `secret` / `service_role` 키는 **절대 쓰지 마세요.** 모든 기록을 열 수 있는 키예요.

주소와 공개 키는 공개돼도 괜찮아요. 기록은 3의 SQL이 만든 규칙 때문에 **로그인한 본인만** 읽고 쓸 수 있고, 5 때문에 새 계정도 못 만들어요.

## 4. 서버 주소·공개 키를 앱에 넣기

`src/config.js`의 두 줄을 채우고 다시 올립니다 (Claude에게 두 값을 알려 주면 넣어서 미리 보기로 먼저 올려 줘요).

```js
export const SUPABASE_URL = 'https://xxxx.supabase.co';
export const SUPABASE_ANON_KEY = 'sb_publishable_…';
```

이렇게 하면 앱의 계정 화면에는 **이메일·비밀번호·로그인**만 보여요. 넣지 않으면 계정 화면에서 기기마다 주소와 키를 직접 넣을 수 있어요.

## 5. 두 기기에서 로그인

설정 › **계정 · 동기화** (처음 화면이라면 **다른 기기에서 쓰던 기록이 있어요**)

**먼저 쓰던 기기** (기록이 있는 쪽)
- 로그인하면 "이 기기에도 기록이 있어요"가 떠요 → **이 기기 기록을 계정에 합치기**

**새 기기**
- 로그인하면 묻지 않고 계정 기록을 받아 와요 → "계정에서 과목 N개 · 할 일 M개를 받아 왔어요"

**예시를 보던 기기**
- 로그인하면 "예시 지우고 로그인"을 물어요. 예시는 계정에 절대 올라가지 않아요.

**맞춰지는 방식**
- 앱을 열 때, 앱으로 돌아올 때, 켜 두면 45초마다 저절로 맞춰져요.
- 두 기기에서 같은 것을 고치면 **나중에 고친 쪽**이 남아요.
- 화면 설정(디자인·글꼴·글자 크기·태블릿 배치)은 기기마다 따로예요. 공부 가능 시간과 쉬는 요일은 같이 써요.
- 로그인이 풀리거나 오래 못 맞추면 **설정 단추에 빨간 점**이 찍혀요. 문제가 없으면 아무것도 안 보여요.
- **미리 보기**(주황 아이콘)도 같은 계정으로 로그인할 수 있어요. 기록은 실제 앱과 따로 맞춰져요 (서버에 `preview:`로 저장).

## 6. 앱을 고친 뒤 올리기 (업데이트)

1. 바뀐 파일을 GitHub에 올리기 전에 PC에서 `python tools/bump_sw.py` (버전 값을 새로 계산)
2. 먼저 미리 보기로: `python tools/preview.py "무엇을 바꿨나" --push` → https://arronkang.github.io/hoedok-planner/preview/
3. 사용자가 확인하고 "올려 줘" → main에 합치고 올리기
4. 기기에서 앱을 다시 열면 **"새 버전이 준비됐어요 · 새로 고침"**

## 7. 문제가 생기면

| 보이는 것 | 할 일 |
|---|---|
| "서버에 동기화용 표가 없어요" | 3-3의 SQL을 실행했는지 확인 |
| "서버 키가 맞지 않아요" | publishable / anon 키를 다시 복사 (secret 아님) |
| "이메일이나 비밀번호가 맞지 않아요" | 3-4에서 만든 이메일·비밀번호 확인. 잊었으면 Authentication › Users에서 계정을 눌러 새 비밀번호 |
| "이 서버는 새 가입을 받지 않아요" | 정상이에요 (3-5). 계정은 3-4처럼 관리 화면에서 만들어요 |
| 설정 단추에 빨간 점 · "로그인이 풀렸어요" | 설정 › 계정 · 동기화에서 다시 로그인. 기록은 그대로예요 |
| 한동안 안 썼더니 동기화가 안 됨 | Supabase 무료 프로젝트는 1주일 안 쓰면 멈춰요. 대시보드에서 **Restore project**. 기록은 기기에 있으니 앱은 그대로 쓸 수 있어요 |
| "이 브라우저에서는 기록을 저장할 수 없어요" | 사생활 보호(시크릿) 창이면 일반 창이나 홈 화면 아이콘으로 열기 |
| 기기를 바꿔요 | 새 기기에서 로그인, 또는 설정 › 자료 › 파일로 내보내기 → 새 기기에서 불러오기 |

## PC에서 시험해 보기 (개발용)

```
python serve.py                        # http://localhost:5173 — 실제 앱
python serve.py 5173 --lan             # 같은 와이파이의 기기에서 열기 (설치는 안 됨)
python tools/fake_supabase.py 54321 --dump --no-signup   # 가짜 동기화 서버 http://127.0.0.1:54321 (키 test-anon-key)
powershell -File tools/node.ps1 tests/run-node.js        # 테스트
```
- 가짜 서버에는 시험용 계정이 하나 들어 있어요. `tools/fake_supabase.py` 위쪽을 보세요.
- `localhost:5173`과 `127.0.0.1:5173`은 저장 공간이 따로라서 두 기기처럼 시험할 수 있어요. 무엇을 확인하는지는 [동기화-체크리스트.md](동기화-체크리스트.md).
- localhost에서는 고친 파일이 바로 보이도록 오프라인 저장(서비스 워커)을 켜지 않아요. 켜 보려면 브라우저 콘솔에서 `localStorage.setItem('hoedok.sw','1')`.
- 화면 전수 점검(글꼴 × 글자 크기 × 디자인): 앱 화면 콘솔에서 `(await import('/tests/layout-check.js')).run()`
