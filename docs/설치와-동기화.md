# 설치와 동기화 안내

앱은 **인터넷 주소에 올려 두고, 휴대폰·태블릿에서 그 주소를 홈 화면에 추가**해서 씁니다.
앱스토어는 필요 없어요. 두 기기가 같은 기록을 쓰려면 **Supabase**(무료)를 하나 만들면 됩니다.

| 순서 | 할 일 | 필요한 것 | 걸리는 시간 |
|---|---|---|---|
| 1 | 앱을 인터넷에 올리기 | GitHub 계정 (무료) | 10분 |
| 2 | 기기에 설치 | 1에서 받은 주소 | 기기마다 1분 |
| 3 | 동기화 서버 만들기 (선택) | Supabase 계정 (무료) | 10분 |
| 4 | 두 기기에서 로그인 | 3의 주소와 키 | 기기마다 1분 |

3·4를 안 하면 기록은 **그 기기에만** 저장됩니다. 설정 › 자료 › 파일로 내보내기로 옮길 수는 있어요.

---

## 1. 앱을 인터넷에 올리기 (GitHub Pages)

홈 화면 설치와 인터넷 없이 열기는 **https 주소**에서만 됩니다. 집 와이파이 주소(`http://PC-IP:5173`)로는 설치가 안 돼요.

1. https://github.com 에서 가입합니다.
2. 오른쪽 위 **+ › New repository**
   - 이름: 예) `hoedok-planner`
   - **Public**으로 둡니다. 무료 계정의 Pages는 공개 저장소만 됩니다.
   - 올라가는 건 앱 코드뿐이고, 공부 기록은 올라가지 않아요.
3. 만든 저장소에서 **Add file › Upload files**를 누르고, `study-planner` 폴더 안의 아래 것들을 끌어다 놓은 뒤 **Commit changes**를 누릅니다.
   - 파일: `index.html`, `manifest.webmanifest`, `sw.js`
   - 폴더: `icons`, `styles`, `src`
   - `docs`, `tests`, `tools`, `archive`는 올리지 않아도 됩니다.
4. 저장소의 **Settings › Pages**로 갑니다.
   - Source: **Deploy from a branch**
   - Branch: **main**, 폴더: **/ (root)**
   - **Save**를 누릅니다.
5. 1~2분 뒤 같은 화면 위쪽에 주소가 뜹니다. 예) `https://내아이디.github.io/hoedok-planner/`

> 동기화 서버 주소를 미리 넣어 두고 싶으면, 올리기 전에 `src/config.js`의 두 줄을 채우세요(3단계 참고). 그러면 기기마다 주소를 입력하지 않아도 됩니다.

## 2. 기기에 설치 (홈 화면에 추가)

**아이폰 (Safari)**
1. Safari로 1에서 받은 주소를 엽니다. 크롬 등 다른 앱에서는 안 돼요.
2. 아래쪽 **공유 버튼(□↑) › 홈 화면에 추가 › 추가**
3. 홈 화면의 아이콘으로 여세요.
   - 아이폰은 홈 화면에 추가하지 않고 Safari에서만 쓰면, 7일 넘게 안 열었을 때 저장된 기록을 지울 수 있어요.
   - 꼭 아이콘으로 쓰고, 동기화나 파일 내보내기도 해 두세요.

**갤럭시 탭 (삼성 인터넷)**
1. 삼성 인터넷으로 주소를 엽니다.
2. 아래쪽 **메뉴(≡) › 현재 페이지 추가 › 홈 화면**
   - 버전에 따라 주소창 옆 설치 아이콘(↓)이 보이면 그걸 눌러도 됩니다.
3. 홈 화면 아이콘으로 엽니다. 주소창 없이 앱처럼 꽉 차게 떠요.

한 번 연 뒤에는 **인터넷이 없어도 열리고 체크도 돼요.** 동기화는 인터넷이 되면 저절로 맞춰집니다.

## 3. 동기화 서버 만들기 (Supabase)

1. https://supabase.com 에서 가입합니다. GitHub 계정으로 가입해도 돼요.
2. **New project**를 누릅니다.
   - 이름: 아무거나
   - Database Password: 아무거나 길게. 앱에서는 쓰지 않지만 적어 두세요.
   - Region: **Northeast Asia (Seoul)**
3. 만들어지면 왼쪽 **SQL Editor › New query**로 갑니다.
   - 이 폴더의 `supabase/schema.sql` 내용을 **전부 복사해 붙여 넣고 Run**을 누릅니다.
   - "Success"가 뜨면 됩니다. 여러 번 실행해도 괜찮아요.
4. 왼쪽 **Authentication › Sign In / Providers › Email**
   - 혼자 쓰는 앱이라 **Confirm email**을 끄면 편해요. 켜 두면 가입 후 메일의 링크를 눌러야 로그인됩니다.
   - 켜 둔다면 **Authentication › URL Configuration › Site URL**에 1의 앱 주소를 넣으세요.
5. 왼쪽 아래 **Project Settings › API** (또는 **Data API / API Keys**)에서 두 값을 복사합니다.
   - **Project URL**: `https://xxxx.supabase.co`
   - **anon public** 키 또는 **publishable** 키
   - `service_role` / `secret` 키는 **절대 쓰지 마세요.** 이 키는 모든 기록을 열 수 있어요.

이 두 값(주소, 공개 키)은 공개돼도 괜찮습니다. 기록은 3단계의 SQL이 만든 규칙 때문에 **로그인한 본인만** 읽고 쓸 수 있어요.

## 4. 두 기기에서 로그인

**먼저 쓰던 기기** (기록이 있는 쪽)
1. 설정 › 자료 › **계정 · 동기화**로 갑니다.
2. 주소와 공개 키를 넣고 **저장**을 누릅니다. `src/config.js`에 넣었으면 이 단계는 없어요.
3. 이메일과 비밀번호(6자 이상)를 넣고 **처음이면 가입**을 누릅니다.
4. "이 기기에도 기록이 있어요"가 뜨면 **이 기기 기록을 계정에 합치기**를 고릅니다.

**새 기기**
1. 앱 첫 화면에서 **다른 기기에서 쓰던 기록이 있어요**를 누릅니다.
2. 주소와 키를 넣고, 같은 이메일로 **로그인**합니다.
3. 잠시 뒤 기록이 모두 들어옵니다. 사진은 열 때 받아 와요.

**맞춰지는 방식**
- 앱을 열 때, 앱으로 돌아올 때, 켜 두면 45초마다 저절로 맞춰집니다.
- 두 기기에서 같은 것을 동시에 고치면 **나중에 고친 쪽**이 남습니다.
- 다른 기기에서 체크한 할 일은 이 기기의 진도 칸에도 채워져요.
- 디자인·글자 크기·태블릿 배치는 기기마다 따로예요. 공부 가능 시간과 쉬는 요일은 두 기기가 같이 씁니다.

## 5. 앱을 고친 뒤 올리기 (업데이트)

1. PC에서 `python tools/bump_sw.py`를 실행합니다. 버전 값을 새로 계산해 `sw.js`에 넣어요.
2. 바뀐 파일을 GitHub 저장소에 다시 **Upload files**로 올립니다. `sw.js`도 꼭 같이 올리세요.
3. 기기에서 앱을 다시 열면 **"새 버전이 준비됐어요 · 새로 고침"**이 뜹니다. 누르면 바뀐 앱으로 열려요.

## 6. 문제가 생기면

| 보이는 것 | 할 일 |
|---|---|
| "서버에 동기화용 테이블/함수가 없습니다" | 3단계의 SQL을 실행했는지 확인 |
| "서버 키가 올바르지 않습니다" | anon/publishable 키를 다시 복사 (service_role 아님) |
| "가입 확인 메일의 링크를 먼저 눌러 주세요" | 메일 확인, 또는 4단계에서 Confirm email 끄기 |
| 한동안 안 썼더니 동기화가 안 됨 | Supabase 무료 프로젝트는 1주일 안 쓰면 멈춰요. 대시보드에서 **Restore project**. 기록은 기기에 있으니 앱은 그대로 쓸 수 있어요 |
| "이 브라우저에서는 기록을 저장할 수 없어요" | 사생활 보호(시크릿) 창이면 일반 창이나 홈 화면 아이콘으로 열기 |
| 기기를 바꿔요 | 새 기기에서 로그인, 또는 설정 › 자료 › 파일로 내보내기 → 새 기기에서 불러오기 |

## PC에서 시험해 보기 (개발용)

```
python serve.py                        # http://localhost:5173 — 실제 앱
python serve.py 5173 --lan             # 같은 와이파이의 기기에서 열기 (설치는 안 됨)
python tools/fake_supabase.py          # 가짜 동기화 서버 http://127.0.0.1:54321 (키 test-anon-key)
powershell -File tools/node.ps1 tests/run-node.js   # 테스트
```
- 가짜 서버에는 시험용 계정이 하나 들어 있습니다. `tools/fake_supabase.py` 위쪽을 보세요.
- `localhost:5173`과 `127.0.0.1:5173`은 저장 공간이 따로라서, 두 기기처럼 동기화를 시험할 수 있어요.
- localhost에서는 고친 파일이 바로 보이도록 오프라인 저장(서비스 워커)을 켜지 않습니다. 켜 보려면 브라우저 콘솔에서 `localStorage.setItem('hoedok.sw','1')`을 실행하세요.
